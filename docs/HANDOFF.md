# 작업 현황 (인수인계)

다른 AI 도구나 새 대화에서 이어서 작업할 때 이 문서부터 읽는다. 규칙은 `AGENTS.md`, 설계는 `docs/DESIGN.md`.
작업을 마칠 때마다 이 문서를 고친다.

마지막 갱신: 2026-10-14 (인도네시아어 500장)

## 사용자

- 시드니에서 일하는 한국인 간호사. 개발을 모르는 비개발자라서 설명은 쉬운 한국어로, 할 일은 단계별로 안내한다.
- 폰: 안드로이드, **삼성 인터넷**으로 홈 화면에 설치해서 쓴다. 다크 모드.
- 배우는 언어: 중국어(심장 병동 간호), 스페인어(스페인 여행, 영어 뜻), 인도네시아어.
- 모든 것이 무료여야 한다. 데이터는 폰 밖으로 나가면 안 된다 (예외: 사용자가 연결한 Gemini, Google Drive).

## 저장소와 배포

- GitHub: `AminJHK/flashcards` (공개). 앱 주소: `https://aminjhk.github.io/flashcards/`
- 브랜치: `main`에 올리면 GitHub Actions(`.github/workflows/deploy.yml`)가 `npm run check` → 빌드 → `gh-pages` 브랜치로 배포한다.
  `claude/mvp`는 지금까지 작업한 브랜치로, `main`과 같은 내용이다.
- 배포 확인: `gh-pages` 브랜치의 최신 커밋 메시지가 `Deploy <커밋 앞 7자리>`이면 끝난 것.
  배포 단계가 GitHub 쪽 일시 오류(`fatal error in commit_refs`)로 실패하면 실패한 작업만 다시 돌리면 된다.
- 설정 화면 맨 아래에 빌드 버전(커밋 앞 7자리)이 보인다. 사용자에게 업데이트를 확인시킬 때 이 값을 알려준다.
  업데이트는 앱을 완전히 닫았다가 다시 열면 받는다 (앱이 다시 보일 때도 새 버전을 확인함).

## 개발

```bash
npm ci
npm run check      # lint + 타입 검사 + 단위 테스트 (푸시 전 필수)
npm run e2e        # Playwright 화면 테스트 (Chromium 필요, 모바일 Pixel 7 화면)
npm run dev        # 개발 서버
```

- 화면 테스트 스크린샷은 `test-results/shots/`에 저장된다. UI를 바꾸면 라이트·다크 둘 다 눈으로 확인한다.
- 실제 Gemini·Google 서버는 테스트에서 가짜 응답(page.route)으로 대신한다. 진짜 키나 실제 사용자 데이터를 쓰지 않는다.

## 지금 있는 기능

- **복습:** FSRS-6 (ts-fsrs 5.4.2). 2버튼/4버튼, 되돌리기, 짧은 간격 카드는 정해진 시간까지 기다림
  (설정 "기다리는 카드 미리 보기": 끄기 기본 / 5분 / 20분).
- **카드 종류:** 중국어 단어, 기본(단어/뜻), 중국어 작문(쓰기·말하기), 중국어 듣기, 스페인어 동사 변화(6인칭).
- **방향:** 덱마다 정방향/역방향 스위치 (둘 중 하나는 켜짐). 언어 설정 이름은 "배우는 언어 / 뜻 언어".
- **준비된 덱 (`src/core/packs/`):**
  - 심장 병동 간호 중국어 (작문·듣기 213개)
  - 여행 스페인어 (명사 354 + 동사 160, 영어 뜻, 기본값 영어 → 스페인어)
  - 스페인어 불규칙 동사 (현재형 35 + 과거형 15)
  - 인도네시아어 구어체 500장 (카드 종류 `id-spoken`). 1~100장은 주제순, 101~500장은 빈도순. Anki용 CSV와 검수 메모: `docs/decks/`. 현지인 검증은 아직 안 함
- **음성:** Gemini TTS(무료 키, 음성 파일을 폰에 저장) → 실패하면 기기 음성. 기기에 그 언어 음성이 없으면 영어로 억지로 읽지 않고 안내한다.
- **말해서 답하기:** Gemini 받아쓰기, 없으면 브라우저 음성 인식(이어 듣기, 중복 제거, 파형 표시).
- **통계:** 복습 히트맵(Anki 스타일), 덱별 기억 상태 막대, 단어마다 기억 단계·확률·다음 복습 (약한 순 정렬).
- **새 덱 화면:** 준비된 덱은 한 줄씩(설명 두 줄까지) 목록으로. 이미 설치한 꾸러미는 아래 "이미 추가한 준비된 덱"에 한 줄로 모이고, 새 단어가 있으면 "기존 덱에 넣기" 버튼이 뜬다 (`useInstalledPacks`, 그 꾸러미 단어가 가장 많은 덱에 넣는다).
- **준비된 덱에 단어 추가:** 꾸러미 뒤에 단어를 붙이면, 이미 설치한 덱 화면에 "준비된 덱에 새 단어 N개가 생겼어요 → 새 단어 받기"가 뜬다 (`packAdditions`, `addPackNotes`). 이미 받은 단어 중 가장 뒤의 것 다음부터만 넣으므로 사용자가 지운 단어는 다시 안 들어온다. 꾸러미 중간에 끼우거나 순서를 바꾸지 말 것. 두 기기에서 동기화 전에 각각 받으면 단어가 두 벌 생길 수 있다 (한 기기에서 받고 동기화하도록 안내).
- **준비된 덱 업데이트:** 꾸러미 내용을 고치면 이미 설치한 덱 화면에 "준비된 덱이 고쳐졌어요"가 뜨고 받을 수 있다 (`src/core/packs/update.ts`). 사용자가 고친 단어(updatedAt ≠ createdAt)는 건드리지 않는다. 꾸러미의 단어(앞면)를 바꾸면 매칭이 안 되니 뜻·메모만 고칠 것.
- **폰 ↔ PC 동기화:** Drive의 `flashcards-sync.json` 하나를 합치기 방식으로 같이 쓴다 (docs/DESIGN.md §3 "기기 사이 동기화"). 앱은 바로 열리고 **로그인 창을 마음대로 띄우지 않는다.** 동기화는 사용자가 배지·"지금 동기화"를 누를 때만 (사용자가 "창이 자꾸 뜨는 게 거슬린다"고 해서 기본 꺼짐). 설정 "처음 누를 때 자동 로그인"을 켜면 앱을 연 뒤 처음 누를 때 창이 잠깐 떴다 닫히며 맞춘다 (`src/ui/FirstTapSync.tsx`). 복습을 닫을 때 받아 둔 토큰이 없으면 "배지를 누르라"고 알린다. 그 뒤로 5분마다·앱이 뒤로 갈 때·복습을 끝내거나 닫을 때 자동 (창 없이, 받아 둔 토큰이 있을 때만). "Google로 로그인하고 시작" 시작 화면은 설정 "시작 화면에서 로그인"을 켠 경우만. 서버가 없어서 로그인을 계속 유지할 수는 없다 (토큰 1시간, 메모리에만 — AGENTS.md 규칙). 버튼이 직접 팝업·파일 창을 연 탭은 양보한다 (`adapters/activation.ts`). 새 기기는 클라이언트 ID를 붙여넣고 로그인하면 불러온다. 두 기기 화면 테스트: `e2e/drive.spec.ts`.
- **동기화 상태 표시:** 왼쪽 위 구석의 작은 구름 아이콘 (`SyncBadge`, `.sync-corner`; 복습·편집 화면에서는 숨김). ☁✓ 동기화됨(회색) / ☁↑ + 숫자 = 올리지 않은 기록 수(주황) / ☁! 실패 / 돌면 동기화 중. 글자는 hover·aria-label에만 ("동기화됨 · 방금 · 종료해도 돼요"). 누르면 바로 동기화. 복습 끝 화면에는 설명 글자가 붙은 inline 버전. 숫자는 `useSyncStatus`: 마지막 동기화 뒤의 복습 기록·바뀐 단어·덱·지운 것 수. 못 올린 게 있는데 창을 닫으면 브라우저가 한 번 묻는다 (beforeunload). 백업(날짜별 복원용 파일)과 동기화(기기끼리 합치는 파일 하나)는 다른 것이라 "백업" 문구는 설정 화면에서만 쓴다: 오늘 화면의 "오늘 아직 Drive에 백업하지 않았어요"와 복습 끝 화면의 "Drive에 백업하고 홈으로"는 사용자 요청으로 없앴다 (Drive를 연결하지 않은 경우의 파일 백업 알림만 남김).
- **앱 업데이트:** 서비스 워커가 새 버전을 늦게 받는 문제(특히 Dock·설치 앱, 창을 닫아도 앱이 안 끝나는 맥)를 피하려고, 빌드가 `version.json`을 내보내고 앱이 열 때·다시 볼 때·10분마다 비교한다 (`adapters/update/update.ts`, `UpdateBanner`). 다르면 **자동으로** 받아서 다시 연다 (복습 중·단어 입력 중·새 덱 화면에서는 끊지 않고 알림만 보이다가 그 화면을 나가면 바로 적용; 같은 버전은 5분 안에 자동 재시도하지 않아 새로고침 반복을 막는다). 알림의 "지금 업데이트" 버튼, 설정 맨 아래 "업데이트 확인" 버튼도 있다. 확인 주기는 2분. 업데이트는 서비스 워커와 파일 캐시만 지우고 `?v=`로 다시 불러온다 (IndexedDB는 건드리지 않음). 이 기능이 들어가기 전 버전에서는 사용자가 한 번은 직접 새로고침해야 한다.
- **앱으로 설치:** 설정 맨 위 "앱으로 설치" (`usePwaInstall`, beforeinstallprompt). 설치한 앱도 같은 브라우저 저장소를 쓰므로 덱·기록이 그대로 보인다 (같은 크롬 프로필 기준).
- **복습을 닫으면** (X 버튼, "나중에 하기", 끝 화면 모두) 항상 메인(오늘) 화면으로 간다. 덱 화면으로 돌려보내지 않는다.
- **PC 키보드(복습):** 스페이스·엔터 = 정답 보기, 1·2 = 다시·알았음 (4버튼이면 1~4), R = 발음 듣기 (Ctrl/Cmd/Alt와 같이 누르면 무시). 마우스가 있는 기기에서는 버튼에 단축키가 표시된다 (`.key-hint`).
- **PC 화면:** 너비 900px 이상이면 왼쪽 세로 메뉴(탭 바가 옆으로 옴) + 가운데 본문(880px, 아주 넓으면 1000px), 덱 목록 2열, 복습 카드 글자 크게. 폰 화면 CSS는 그대로 두고 `src/ui/styles.css` 맨 아래 `@media (min-width: 900px)`에서만 바꾼다. 화면 테스트: `e2e/desktop.spec.ts`(1440×900 스크린샷 30~36번).
- **백업:** 파일 내보내기/가져오기, Google Drive 백업(사용자가 만든 OAuth 클라이언트 ID). 키와 토큰은 백업에 넣지 않는다.

## 아직 실제 폰에서 확인하지 못한 것

- 방금 답한 카드가 다시 나오던 문제 (알았음 1일 → 같은 카드가 2일로): 저장을 기다리는 동안 그 카드가 화면에 남아 있다가, 저장이 끝나면 버튼 간격만 바뀌어 같은 카드가 또 나온 것처럼 보였다(느린 폰에서 6초 제한에 걸리면 그대로 남음). 이제 누르는 즉시 다음 카드로 넘어가고 저장은 뒤에서 한다(실패하면 알리고 그 카드를 되돌린다). 답한 카드는 목록에 반영될 때까지 `assumeAnswered`로 숨긴다. 저장을 3초 막는 화면 테스트로 확인.

- 상태 표시줄 색: 삼성 인터넷 설치 앱은 theme-color(동적·media 둘 다 넣음)를 무시하고 검게 칠했다. 사용자는 전체 화면(쓸어내리면 바가 나옴)을 싫어해서 `immersive`는 기본 꺼짐. 앱 다크 테마+완전 검정 배경이면 이어져 보이고, Chrome으로 설치하면 theme-color를 따를 가능성이 있다 (미확인).

자동 테스트는 통과했지만 사용자 폰에서 확인이 필요한 것들. 사용자가 다시 문제를 말하면 여기부터 본다.

- 버튼이 가끔 안 눌리던 문제: 확인 창을 앱 안의 창으로 바꾸고, 저장 6초 제한·오류 알림을 넣었다. 원인은 끝내 재현하지 못했다.
- 기기 음성으로 스페인어 읽기: 음성 목록이 늦게 오는 문제를 고쳤다. 사용자의 덱은 "배우는 언어"가 영어로 바뀌어 있었으니 스페인어로 되돌렸는지 확인할 것.
- Gemini 음성이 지시문("Say in …")까지 읽던 문제: 프롬프트를 줄이고 예전 음성 파일을 지웠다.
