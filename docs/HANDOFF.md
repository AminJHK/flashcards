# 작업 현황 (인수인계)

다른 AI 도구나 새 대화에서 이어서 작업할 때 이 문서부터 읽는다. 규칙은 `AGENTS.md`, 설계는 `docs/DESIGN.md`.
작업을 마칠 때마다 이 문서를 고친다.

마지막 갱신: 2026-10-20 (이야기가 비슷하게 나오던 문제·어려운 단어 넣기, 읽기 받아쓰기, aja 연습 덱, 읽기 "듣고 읽기", 안드로이드 앱 시작, 기기 음성 기본 목소리·속도·높낮이, 인도네시아어 영어 뜻 · 자주 쓰는 표현, 읽기 의미 단위 없앰, 어려운 단어)

## 사용자

- 시드니에서 일하는 한국인 간호사. 개발을 모르는 비개발자라서 설명은 쉬운 한국어로, 할 일은 단계별로 안내한다.
- 폰: 안드로이드, **삼성 인터넷**으로 홈 화면에 설치해서 쓴다. 다크 모드.
- 배우는 언어: 중국어(심장 병동 간호), 스페인어(스페인 여행, 영어 뜻), 인도네시아어.
- 모든 것이 무료여야 한다. 데이터는 폰 밖으로 나가면 안 된다 (예외: 사용자가 연결한 Gemini, Google Drive).

## 저장소와 배포

- GitHub: `AminJHK/flashcards` (공개). 앱 주소: `https://aminjhk.github.io/flashcards/`
- 브랜치: `main`에 올리면 GitHub Actions(`.github/workflows/deploy.yml`)가 `npm run check` → 빌드 → `gh-pages` 브랜치로 배포한다.
  `claude/mvp`는 지금까지 작업한 브랜치로, `main`과 같은 내용이다.
- 배포 확인: `gh-pages` 브랜치의 최신 커밋 메시지가 `Deploy <커밋 앞 7자리>`이면 끝난 것.
  배포 단계가 GitHub 쪽 일시 오류(`fatal error in commit_refs`)로 실패하면 실패한 작업만 다시 돌리면 된다.
- 설정 화면 맨 아래에 빌드 버전(커밋 앞 7자리)이 보인다. 사용자에게 업데이트를 확인시킬 때 이 값을 알려준다.
  업데이트는 앱을 완전히 닫았다가 다시 열면 받는다 (앱이 다시 보일 때도 새 버전을 확인함).

## 개발

```bash
npm ci
npm run check      # lint + 타입 검사 + 단위 테스트 (푸시 전 필수)
npm run e2e        # Playwright 화면 테스트 (Chromium 필요, 모바일 Pixel 7 화면)
npm run dev        # 개발 서버
```

- 화면 테스트 스크린샷은 `test-results/shots/`에 저장된다. UI를 바꾸면 라이트·다크 둘 다 눈으로 확인한다.
- 실제 Gemini·Google 서버는 테스트에서 가짜 응답(page.route)으로 대신한다. 진짜 키나 실제 사용자 데이터를 쓰지 않는다.

## 안드로이드 앱 (2026-10-18 시작)

- 사용자 요청: 엔진을 고를 수 있는 음성(삼성 TTS 선호), 휴대폰 설정의 속도·높낮이, 나중에 복습 알림·Fish Audio 등을 위해 안드로이드 앱으로. 자세한 내용은 **`docs/ANDROID.md`**.
- Capacitor 앱이 배포된 웹앱을 불러온다 → 웹 배포가 곧 앱 업데이트. APK는 GitHub Actions(`android.yml`)가 서명 없이 만들어 릴리스 `android-latest`에 올리고, 서명해서 사용자에게 준다. **서명 키는 저장소에 없다** — 사용자가 자기 Drive에 보관 (ANDROID.md).
- 앱 안 Google 로그인은 네이티브 방식(`NativeGooglePlugin`)이고, 사용자가 Google Cloud에 Android 클라이언트를 한 번 만들어야 한다. 서명 키는 사용자 Drive에 보관(키가 필요하면 사용자에게 받는다). 다음 단계: 복습 알림.

## 지금 있는 기능

- **복습:** FSRS-6 (ts-fsrs 5.4.2). 2버튼/4버튼, 되돌리기, 짧은 간격 카드는 정해진 시간까지 기다림
  (설정 "기다리는 카드 미리 보기": 끄기 기본 / 5분 / 20분).
- **카드 종류:** 중국어 단어, 기본(단어/뜻), 중국어 작문(쓰기·말하기), 중국어 듣기, 스페인어 동사 변화(6인칭).
- **방향:** 덱마다 정방향/역방향 스위치 (둘 중 하나는 켜짐). 언어 설정 이름은 "배우는 언어 / 뜻 언어".
- **준비된 덱 (`src/core/packs/`):**
  - 심장 병동 간호 중국어 (작문·듣기 213개)
  - 여행 스페인어 (명사 354 + 동사 160, 영어 뜻, 기본값 영어 → 스페인어)
  - 스페인어 불규칙 동사 (현재형 35 + 과거형 15)
  - 인도네시아어 구어체 1250장 (카드 종류 `id-spoken`). 1~100장은 주제순, 101~500장·501~1000장은 묶음마다 빈도순, 1001~1250장은 실생활 쓸모순(2026-10-23, 사용자 요청) (묶음은 뒤에 이어 붙임, 앞 순서는 절대 바꾸지 않는다). Anki용 CSV(`indonesian_colloquial.csv`)와 검수 메모: `docs/decks/`. 현지인 검증은 아직 안 함
- **음성:** Gemini TTS(무료 키, 음성 파일을 폰에 저장) → 실패하면 기기 음성. 기기에 그 언어 음성이 없으면 영어로 억지로 읽지 않고 안내한다.
- **말해서 답하기:** Gemini 받아쓰기, 없으면 브라우저 음성 인식(이어 듣기, 중복 제거, 파형 표시).
- **통계:** 복습 히트맵(Anki 스타일), 덱별 기억 상태 막대, 단어마다 기억 단계·확률·다음 복습 (약한 순 정렬).
- **새 덱 화면:** 준비된 덱은 한 줄씩(설명 두 줄까지) 목록으로. 이미 설치한 꾸러미는 아래 "이미 추가한 준비된 덱"에 한 줄로 모이고, 새 단어가 있으면 "기존 덱에 넣기" 버튼이 뜬다 (`useInstalledPacks`, 그 꾸러미 단어가 가장 많은 덱에 넣는다).
- **준비된 덱에 단어 추가:** 꾸러미 뒤에 단어를 붙이면, 이미 설치한 덱 화면에 "준비된 덱에 새 단어 N개가 생겼어요 → 새 단어 받기"가 뜬다 (`packAdditions`, `addPackNotes`). 이미 받은 단어 중 가장 뒤의 것 다음부터만 넣으므로 사용자가 지운 단어는 다시 안 들어온다. 꾸러미 중간에 끼우거나 순서를 바꾸지 말 것. 두 기기에서 동기화 전에 각각 받으면 단어가 두 벌 생길 수 있다 (한 기기에서 받고 동기화하도록 안내).
- **준비된 덱 업데이트:** 꾸러미 내용을 고치면 이미 설치한 덱 화면에 "준비된 덱이 고쳐졌어요"가 뜨고 받을 수 있다 (`src/core/packs/update.ts`). 사용자가 고친 단어(updatedAt ≠ createdAt)는 건드리지 않는다. 꾸러미의 단어(앞면)를 바꾸면 매칭이 안 되니 뜻·메모만 고칠 것.
- **폰 ↔ PC 동기화:** Drive의 `flashcards-sync.json` 하나를 합치기 방식으로 같이 쓴다 (docs/DESIGN.md §3 "기기 사이 동기화"). 앱은 바로 열리고 **로그인 창을 마음대로 띄우지 않는다.** 동기화는 사용자가 배지·"지금 동기화"를 누를 때만 (사용자가 "창이 자꾸 뜨는 게 거슬린다"고 해서 기본 꺼짐). 설정 "처음 누를 때 자동 로그인"을 켜면 앱을 연 뒤 처음 누를 때 창이 잠깐 떴다 닫히며 맞춘다 (`src/ui/FirstTapSync.tsx`). 그 뒤로 5분마다·앱이 뒤로 갈 때·복습을 끝내거나 닫을 때 자동 (창 없이, 받아 둔 토큰이 있을 때만). "Google로 로그인하고 시작" 시작 화면은 설정 "시작 화면에서 로그인"을 켠 경우만. 서버가 없어서 로그인을 계속 유지할 수는 없다 (토큰 1시간, 메모리에만 — AGENTS.md 규칙). 버튼이 직접 팝업·파일 창을 연 탭은 양보한다 (`adapters/activation.ts`). 새 기기는 클라이언트 ID를 붙여넣고 로그인하면 불러온다. 두 기기 화면 테스트: `e2e/drive.spec.ts`.
- **읽기 (AI 이야기, 하단 메뉴 "읽기"):** 내 덱의 FSRS 상태로 고른 단어로 Gemini가 대화형 이야기를 만들고, 앱이 단어 비율·질문을 직접 검사한다 (docs/DESIGN.md §6.3). 한 줄씩 열리는 화면, 질문 4종류, 단어 누르면 뜻·덱에 추가, 문장마다 🔊·자동 읽기 토글. **이야기 만들기는 뒤에서 돈다** (`src/ui/storyJob.ts`: 모듈 단위 작업이라 화면을 옮겨도 계속, 끝나면 `StoryJobWatcher`가 알림만 띄우고 화면은 옮기지 않음, 읽기 탭에 도는 표시·완성 점. 앱을 닫거나 새로고침하면 중단됨). Gemini가 붐비면(503) 2초·6초 뒤 재시도 후 다음 모델로. 한 번에 받지 않고 조금씩 받아(`generateStream`, SSE) 진행률(받은 글자 수 ÷ 어림 4500자)을 카드 막대·퍼센트, 읽기 탭 표시, 어느 화면에서든 맨 위 얇은 막대(`.job-top`)로 보여 준다. 생각하는 시간을 줄여 빠르게 한다: 400이 나면 thinkingBudget 0 → thinkingLevel low → 설정 없음 순서로 같은 모델에 다시 하고, 된 방식을 모델별로 기억한다 (실제 Gemini가 thinkingBudget 0을 400으로 거부한 적 있음). 데이터가 계속 오는 동안은 안 끊고, 60초 동안 아무것도 안 오면 포기(전체 240초). **실제 폰에서 95%에서 멈췄다가 네트워크 오류가 나는 문제가 있었다** → 받은 글이 끝까지 온 JSON이면 연결이 안 닫혀도 바로 끝내고(`isCompleteStory`), 3만 자가 넘으면(같은 말 반복) 끊고 그 답은 버린 채 짧게 다시 요청, `maxOutputTokens` 8192, 단어 목록 450개로 줄이고 glossary는 목록에 없는 단어만. 진행률은 100%에 닿지 않는 곡선(`progressOf`). **그래도 실제 폰에서 3번 다 "쓸 수 있는 결과 없음"으로 실패했다** → (1) `temperature`를 보내지 않음(Gemini 3은 1.0 아래로 낮추면 반복·고장이 난다고 안내), (2) 같은 글을 되풀이하면 바로 끊음(`looksLooping`, 최대 2만 자), (3) 끊긴 JSON은 마지막으로 끝까지 온 블록까지 살려 씀(`core/stories/salvage.ts`), (4) 질문이 3개보다 적어도 줄이 6개 이상이면 쓸 수 있는 후보로 둠(고쳐 달라고만 함), (5) 고쳐 쓰다 실패해도 앞에서 받은 이야기는 버리지 않음, (6) 끝내 실패하면 시도마다 이유(글자 수, finishReason, 문제)를 오류 문구에 담음, (7) 블록마다 그 종류의 필드만 쓰라고 프롬프트에 추가. **다음 실패 문구: 3번 다 등장인물 + 0~3줄에서 끊김** → `maxOutputTokens` 8192에 생각(thinking) 토큰이 같이 들어가서 이야기를 쓸 자리가 없었던 것으로 판단 → 32768로 올리고, Gemini 3 Flash용 `thinkingLevel: 'minimal'`을 low보다 먼저 시도. 오류 문구에 시도마다 [글자 수, finishReason, 생각 토큰 수]를 담는다. 생각 부분(`thought: true`)은 본문에서 뺀다. **그다음 실패: 3번 다 첫 줄도 쓰기 전에 되풀이(3085자·6362자, 0줄), 3번째는 60초 멈춤** → JSON 구조화 출력(responseSchema)을 버리고 **한 줄에 하나씩 쓰는 글 형식**(`core/stories/textFormat.ts`: TITLE/CHARACTER/LINE/CHOICE/TF/GAP/MATCH/GLOSS/END)으로 바꿨다. `parseStoryText`가 예전 JSON과 같은 모양으로 바꿔서 `parseDraft` 검사는 그대로. END가 없으면 끊긴 마지막 줄만 버리고 쓴다(JSON 살리기 `salvage.ts`는 지움). 아직 실제 Gemini로 성공을 확인하지 못했다 — 실패하면 사용자에게 오류 문구 전체를 받을 것. 화면 테스트: `e2e/story.spec.ts`(가짜 Gemini). 진짜 Gemini로는 아직 못 돌려 봤다 — 실제 결과 품질(비율을 맞추는지, 구어체가 자연스러운지)을 사용자에게 확인받을 것. 동기화·백업에는 아직 안 들어간다.
- **동기화 상태 표시:** 오른쪽 위 구석의 작은 구름 아이콘 (Drive 미연결이면 흐린 구름 — 누르면 설정으로) (`SyncBadge` in `ScreenSync` — 각 탭 화면 맨 위 `.screen` 안에 absolute로 들어 있어 스크롤하면 내용과 함께 올라간다. 화면에 떠 있게 만들지 말 것; 복습·편집 화면에는 없음). ☁✓ 동기화됨(회색) / ☁↑ + 숫자 = 올리지 않은 기록 수(주황) / ☁! 실패 / 돌면 동기화 중. 글자는 hover·aria-label에만 ("동기화됨 · 방금 · 종료해도 돼요"). 누르면 바로 동기화. 복습 끝 화면에는 설명 글자가 붙은 inline 버전. 숫자는 `useSyncStatus`: 마지막 동기화 뒤의 복습 기록·바뀐 단어·덱·지운 것 수. 못 올린 게 있는데 창을 닫으면 브라우저가 한 번 묻는다 (beforeunload). 백업(날짜별 복원용 파일)과 동기화(기기끼리 합치는 파일 하나)는 다른 것이라 "백업" 문구는 설정 화면에서만 쓴다: 오늘 화면의 "오늘 아직 Drive에 백업하지 않았어요"와 복습 끝 화면의 "Drive에 백업하고 홈으로"는 사용자 요청으로 없앴다 (Drive를 연결하지 않은 경우의 파일 백업 알림만 남김).
- **앱 업데이트:** 수동. 서비스 워커가 새 버전을 늦게 받는 문제(특히 Dock·설치 앱)를 피하려고 빌드가 `version.json`을 내보내고, 설정 맨 아래에서 비교한다 (`adapters/update/update.ts`). 새 버전이 있으면 설정 맨 아래에만 "새 버전 xxx이 있어요 · 지금 업데이트"가 뜬다. 업데이트는 서비스 워커와 파일 캐시만 지우고 `?v=`로 다시 불러온다 (IndexedDB는 건드리지 않음). 사용자 요청으로 복습 중에 뜨던 알림과 자동 새로고침은 없앴다.
- **앱으로 설치:** 설정 맨 위 "앱으로 설치" (`usePwaInstall`, beforeinstallprompt). 설치한 앱도 같은 브라우저 저장소를 쓰므로 덱·기록이 그대로 보인다 (같은 크롬 프로필 기준).

- **Gemini 무료 사용량이 몇 문장 후 429 (2026-10-16):** 사용자 스크린샷 '기기 음성으로 대체됨 · Gemini 오류: 오늘 무료 사용량을 다 썼거나 너무 빨리 요청했어요' 확인. 실제 429만으로 하루 사용량 소진인지 RPM 제한인지 구분 불가. 기존 구현은 읽기 진입/문장 이동 때 **다음 문장을 백그라운드에서 Gemini로 미리 생성**하고 재생 시 또 요청했으며, 음성 미리 생성 실패를 무시함. 이 방식은 짧은 시간에 요청을 쏟아내므로 **읽기 자동 prefetch를 중단**하고 실제 한 문장을 읽거나 스피커를 누를 때만 요청하도록 변경(성공한 음성 IndexedDB 캐시는 그대로 유지). API의 quota details/quotaId 또는 Retry-After로 분당/일일/미확인 429를 구분해 정확한 한국어 메시지 표시; 분당 오류는 기본 75초, 일일/미확인 오류는 15분간 **동일 모델의 새 TTS 요청을 세션 내에서 차단**하여 연쇄 API 호출 방지(저장된 음성은 계속 재생, 다른 모델은 영향 없음). '모든 단어 음성 미리 만들기'는 분당 제한만 재시도하고 나머지는 정지. Gemini 실패 → 기기 TTS 대체(D7)를 그대로 유지. 장기적으로 사용자 키의 정확한 한도는 AI Studio 프로젝트의 rate limits/usage에서 확인 필요. 화면에 톱니가 없는 스크린샷은 `183bb2d` 미업데이트일 수 있음. CI 통과 여부 및 실제 폰 테스트 필요.

- **스토리 생성 직후 TTS 준비 (2026-10-16):** `startStoryJob`에서 텍스트 스토리를 먼저 저장한 직후 `prepareStoryAudio`를 호출. 문장별 나레이터/캐릭터 음성 설정(`storyVoice`, `roleOf`)과 기존 모델별 IndexedDB 음성 캐시 재사용. 음성은 준비만 하고 재생하지 않음. 읽기 탭에 준비 완료/진행률/중단 사유 표시; 사용자는 음성 준비를 기다리지 않고 읽기 시작 가능. 모델별 분당 무료 요청 제한 준수, 분당 한도는 잠시 기다렸다 재시도(최대 2회), 일일 한도/기타 오류는 즉시 중단하고 이미 만든 음성 보존. 앱 종료/새로고침 시 백그라운드 준비 중단(기존 동작). 음성 캐시는 저장소에서 그대로 유지. **멀티스피커 한 요청 생성 및 문장 단위 오디오 분할은 정확도/모델 호환 검증 전이므로 미구현**; 문장별 TTS를 생성 시점으로 옮긴 1단계 개선임. 따라서 총 무료 요청량이 줄어드는 것은 아니며 사용자가 아직 읽지 않은 문장도 사전 생성되어 하루 한도를 더 빨리 사용할 수 있음. 실물 폰에서 준비 시간/오디오 재생/배경 제한 확인 필요.

## 이야기 생성: "응답이 60초 동안 오지 않아요" (한 글자도 안 옴)
- 원인: Gemini는 쓰기 전에 생각하는 동안 아무것도 보내지 않는다. 의미 단위를 요청하면서 생각이 길어져 첫 글자 전 60초 제한에 걸렸다.
- `generateStream`의 `firstMs`(첫 데이터까지, 이야기는 2분) / `idleMs`(그 뒤 멈춤, 60초) / `totalMs`(5분)를 나눴다. 값은 `story.ts`의 `STREAM_TIMING`.
- 첫 데이터 전에 시간이 다 되면 `GeminiError(kind 'busy', noStart=true)` → 같은 모델로 기다리지 않고 바로 다음 모델(flash-lite)로.
- 읽기는 `Promise.race([reader.read(), aborted])`라서 끊기 신호를 무시하는 연결에서도 시간이 되면 끝난다.

## 이야기·음성 만들기를 서비스 워커에서 (2026-10-20, 사용자가 A안 선택)
- 웹앱을 내리면 브라우저가 화면의 작업을 멈춘다 → 이야기 만들기와 음성 만들기를 **서비스 워커**(`src/sw.ts`)에서 돌린다. vite-plugin-pwa를 `generateSW` → `injectManifest`로 바꿨다 (예전 설정: 미리 저장 `**/*.{js,css,html,svg,png}`, index.html 대체, 폰트 CacheFirst 400개를 sw.ts에 그대로 옮김). workbox-* 패키지를 devDependencies에 추가.
- 실제 일은 `adapters/stories/jobs.ts`(`runStory`, `runAudio`)에 있고 화면과 서비스 워커가 같이 쓴다. 화면(`ui/storyJob.ts`)은 서비스 워커에 `postMessage`로 맡기고, 소식은 `BroadcastChannel('story-jobs')`로 받는다 (ack/step/done/error/audio/status). 3초 안에 ack가 없으면(서비스 워커 없음, 예전 버전) 화면 안에서 돌린다.
- 서비스 워커는 `event.waitUntil`로 끝날 때까지 살려 달라고 한다. 브라우저가 보통 몇 분까지만 살려 두므로 너무 길면 멈출 수 있다 → 화면이 다시 보이면(그리고 보이는 동안 20초마다) `story:status`로 맞춰 보고, 일을 잃었으면 저장된 이야기가 있는지 보고 완성 또는 "앱을 내려 둔 사이 … 멈췄어요"로 바꾼다.
- 다 되면 화면이 안 보일 때만 휴대폰 알림(`showNotification`, tag 'story'): 이야기 완성 → 음성까지 준비(같은 알림을 바꿈). 누르면 그 이야기로. 알림 허락은 "이야기 만들기"를 처음 누를 때 묻는다. 안드로이드 앱(WebView)은 알림이 없다.
- 서비스 워커 안에서는 동적 import를 못 쓴다 (Vite의 preload 도우미가 `import.meta`를 남겨 SW가 안 켜졌다) → speech.ts의 voices를 정적 import로. 서비스 워커에 들어가는 코드에서 `await import()`를 쓰지 말 것.
- 화면 테스트: Gemini 가짜 응답을 `page.context().route`로 (서비스 워커의 요청도 잡힌다). `e2e/story.spec.ts` "백그라운드": 만드는 중에 화면을 닫아도 이야기·음성이 저장된다.

## 어조 말 덱 · 연결어·표현 덱 · 읽기 연동
- **카드 종류 `id-particle`** (`core/cardTypes/idParticle.ts`): 노트 하나 = 예문 하나(같은 말이 여러 노트). 앞면: 「sih」는 여기서 어떤 느낌일까? + 예문, 뒷면: 예문 뜻·말·느낌·이 문장에서. 중복 기준은 말+예문.
- **준비된 덱 `indonesian-particles`** (`core/packs/indonesianParticles.ts`): sih dong deh kok kan lho nih tuh yah nah × 예문 6개 = 60장, 하루 5개. 예문·설명은 AI가 써서 현지인 검증 안 함. 새 말·예문은 파일 끝에 이어서 추가할 것(packAdditions).
- **연결어·표현 덱**: 구어체 덱 화면에 "연결어 따로 모으기" 패널 → `moveConnectors`(repo.ts)가 덱 「연결어·표현」(하루 3개, 예문 먼저)을 만들고 `CONNECTOR_WORDS`(core/decks/connectors.ts, 직접 고른 약 40개)에 든 id-spoken 노트를 옮긴다. 한 트랜잭션에서 bulkPut, 복습 기록·기억 상태는 그대로. yang/di/ke/dari/dan/tapi 같은 기본 단어는 일부러 뺐다.
- **예문 먼저 보기**: `DeckSettings.sentenceFirst`(선택 필드, 마이그레이션 필요 없음). id-spoken 카드의 앞면이 예문(+「단어」는 여기서 무슨 뜻일까?). 덱 설정에 스위치.
- `packAdditions(pack, notes, everywhere)`: 다른 덱으로 옮긴 단어도 "이미 받은 단어"로 세어서, 옮긴 연결어가 새 단어로 다시 들어오지 않는다.
- **읽기 연동**: `buildLexicon`이 id-particle 노트를 말(word)별로 묶어 `kind:'particle'` 항목 하나로 넣는다(안 본 말=deckNew, 본 예문 2개 이상이 모두 단단하면 known). 같은 말이 구어체 덱에도 있으면 같은 상태일 때 어조 말 쪽을 쓰고, 단어 목록에서는 뺀다. `planStory`: `particles`(본 말, 기억 약한 순) + `newParticle`(덱의 다음 안 본 말 하나) → 프롬프트에 "PARTICLE WORDS / NEW PARTICLE, 대화에서만 1~3개, 새 말은 2번 이상". 비율 계산에서 어조 말은 안 배운 말이어도 아는 말로 센다. 이야기에서 어조 말을 누르면 말풍선에 느낌.
- 테스트: `e2e/particles.spec.ts`, `core/stories/stories.test.ts`(어조 말), `core/decks/connectors.test.ts`, `repo.test.ts`(연결어 옮기기).

## 카드 글자 위계
- 폰 기준: 앞면 단어 42 > 앞면 뜻 32 > 앞면 예문 24 / 뒷면 단어 32 > 뜻 22 > 예문 상자(본문 18 · 번역 15) > 메모 14. PC는 비례해서 크게. 같은 쪽에 비슷한 크기의 굵은 줄이 둘 이상 오지 않게 한다.
- `CardFace`에 `side`가 생겼다: 뒷면에서는 예문(main)과 번역(sub)을 `.b-example` 상자 하나로 묶어 왼쪽 정렬. 메모는 상자 없이 작은 글씨. 앞면 예문(예문 먼저 카드)은 그대로 크게.
- 라틴 문자 문장은 모두 `--font-latin`(Noto Sans). Noto Sans 600을 같이 넣었다(없으면 가짜 굵게로 뭉개짐).

## 복습 카드 화면 다시 설계
- 카드 한 장(`.card-sheet`, 둥근 카드 배경) 위에 그린다. 뒷면은 두 칸: 위(가운데) = 첫 예문·메모 전까지의 블록(단어·뜻·꼬리표), 아래(왼쪽 정렬, 카드 폭 선으로 나눔) = 예문(왼쪽 색 막대, 배우는 말은 강조색 굵게)+번역, 메모. 위 칸이 비면(문장이 곧 정답인 카드) 가운데에 크게.
- 블록 추가: `sentence.highlight`(문장 안에서 강조할 말), `tags`(표준형·어근·사용역 꼬리표). 예전처럼 메모에 섞지 않는다. divider는 화면에서 그리지 않는다(칸 나눔으로 대신).
- id-spoken / id-particle 뒷면 순서: 단어 → 뜻 → (꼬리표) → 예문 → 번역 → 메모.
- `CardFace`는 `<span>`만 쓴다(카드 전체가 `<button>`이라 div를 넣으면 안 됨). 테스트: `src/ui/components/CardFace.test.tsx` (vitest에 *.test.tsx 포함).
- 메모는 뒷면 아래 칸에서 "참고" 이름표 + 설명. 메모 안의 따옴표 친 라틴 문자 표현('Tahan dulu')은 예문 글꼴로 진하게(`withQuotes`), 한국어 따옴표는 그대로. 크기: 앞면 단어 48, 뒷면 단어 40·뜻 26, 예문 19·번역 16.

## 지운 단어 되살리기
- 덱 화면에 "지운 단어 N개를 되살릴 수 있어요" 패널: 이 덱에 준비된 덱 단어가 있으면, 원본 꾸러미에는 있는데 어느 덱에도 없는 단어를 `packMissing`(core/packs/update.ts)으로 찾는다. 이미 있는 말(같은 카드 종류·같은 단어, 구어 단어는 철자만 같아도), 어조 말 덱이 맡은 말(`PARTICLE_WORDS`)은 뺀다. 태그(담화표지 등)별로 끄고 켤 수 있고 `addPackNotes`로 새 카드로 넣는다. 「연결어·표현」 덱이 있으면 연결어는 그 덱으로.
- 지운 흔적(tombstone)에는 단어 정보가 없어서 원본 비교로 찾는다. 일부러 지운 단어도 패널에 계속 뜬다(숨기기 없음). 필요하면 "다시 안 보기" 추가.
