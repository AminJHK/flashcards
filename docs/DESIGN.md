# 플래시카드 앱 기획서

- 버전: v0.2 (2026-10-08)
- 상태: 1단계(MVP) 구현됨
- 앱 이름: 미정 (임시 `flashcards`)

---

## 0. 한 줄 요약

**안드로이드 폰에서 매일 열고 싶어지는 개인용 단어 카드 앱.**
최신 FSRS 알고리즘으로 복습 시점을 정하고, 중국어·인도네시아어 발음을 자연스럽게 읽어준다.
웹앱(PWA)으로 만들어 홈 화면에 설치해서 쓴다.

---

## 1. 목표와 범위

### 목표

1. **디자인:** 라이트/다크 모드 모두 보기 좋고, 쓰기 싫어지지 않는 앱
2. **스케줄링:** 공개된 것 중 가장 정확한 알고리즘(FSRS)을 쓰고, 더 좋은 버전이 나오면 갈아탈 수 있는 구조
3. **단어 추가:** 한 화면에서 연속 입력. 중국어 병음은 자동으로 채움
4. **발음(TTS):** 중국어(zh-CN)·인도네시아어(id-ID)를 자연스럽게 읽어줌
5. **대량 입력:** PC에서 스프레드시트로 정리한 단어를 붙여넣기/파일로 가져오기
6. **개인정보:** 카드와 복습 기록은 내 폰에만 저장

### 이번에 안 하는 것

- 여러 사용자, 계정, 로그인
- 기기 간 자동 동기화 (백업 파일로 옮기기만 지원)
- Anki 덱/기록 가져오기
- 사용자가 직접 편집하는 HTML/CSS 카드 템플릿
- 이미지 카드, 공유 덱

## 3. 개인정보와 데이터 보관

### 데이터 위치

- **폰에 저장되는 것:** 카드, 복습 기록, 설정, 음성 파일. 브라우저 저장소(IndexedDB)에 들어감
- **repo에 올라가는 것:** 앱 코드만. 사용자 데이터, API 키, 백업 파일은 절대 커밋하지 않음
- **서버:** 없음. 분석 도구, 광고, 외부 CDN 폰트도 쓰지 않음 (접속 정보가 밖으로 나가지 않게 폰트도 앱에 포함)

### 폰 밖으로 나가는 경우

| 경우 | 나가는 정보 | 받는 곳 |
|---|---|---|
| Gemini 음성을 켰을 때 | 읽어줄 텍스트 (단어/예문) | Google (Gemini API) |
| Gemini 받아쓰기를 켰을 때 | 마이크로 녹음한 답 | Google (Gemini API) |
| 폰 내장 TTS | 폰 설정에 따라 Google 온라인 음성을 쓸 수 있음 | Google |
| 백업 내보내기 | 전체 데이터가 담긴 파일 | 사용자가 고른 위치 (다운로드 폴더, Google Drive 등) |

### API 키 (Gemini)

- 앱 설정 화면에 붙여넣고, **폰 저장소에만** 보관함
- 키 권한은 "TTS API만", "내 앱 주소에서만 사용 가능"으로 제한
- 사용량 알림을 설정함

### 데이터 유실 방지

브라우저 데이터는 Chrome 데이터 삭제, 앱 삭제 등으로 사라질 수 있음. 그래서 아래 세 가지를 함.

- `navigator.storage.persist()`로 "영구 저장"을 요청
- **원탭 백업:** 전체 데이터를 JSON 파일로 내보냄. 안드로이드 공유 시트로 Drive 등에 바로 저장
- **백업 알림:** 마지막 백업 후 7일이 지나면 홈 화면에 조용히 알림

참고: 백업 파일은 암호화하지 않음. 본인 Drive에 보관하는 것을 전제로 함.

## 4. 스케줄링 (SRS)

### 4.1 알고리즘 선택

| | FSRS-6 | FSRS-7 |
|---|---|---|
| 라이브러리 | `ts-fsrs` 5.4.2 (안정판, 2026-09-01) | `ts-fsrs` 6.0.0-beta.13 (베타, 2026-10-03) |
| 벤치마크 log loss (당일 재복습 포함) | 0.3842 | 0.3206 |
| 벤치마크 log loss (당일 재복습 제외) | 0.3460 | 0.3401 |
| 특징 | 간격을 정수 일 단위로 다룸 | 간격을 소수로 다룸. 같은 날 재복습도 정확히 예측 |
| Anki 적용 | 사용 중 | 통합 진행 중 (draft PR, 2026-09) |

**규칙: `ts-fsrs` 6.0이 정식 출시되면 FSRS-7을 기본으로 쓴다.**

**현재 상태 (2026-10-08):** 6.0은 아직 베타(beta.13)이고 API가 크게 바뀌는 중이라 **FSRS-6으로 시작했다.**
- 스케줄러는 `src/core/scheduler/`의 어댑터(`Scheduler` 인터페이스)로 분리돼 있다.
- FSRS-7은 `fsrs7.ts` 어댑터를 하나 만들고 `registry.ts`에 등록하면 된다.
- 설정 화면의 "알고리즘" 줄에 현재 알고리즘을 보여준다. 정식판이 나오면 여기서 고르게 한다.

전환할 때는 로그 전체를 새 알고리즘으로 다시 계산한다(`rebuildAll`, D4). 데이터 손실은 없다.

### 4.2 복습 로그 (원본 데이터)

모든 스케줄링 이벤트는 `ReviewLog`에 **추가만** 한다. 지우거나 고치지 않는다.

| 이벤트 | 의미 |
|---|---|
| `review` | 버튼을 눌러 복습함 |
| `void` | 직전 복습 취소. 취소할 로그 ID를 가리킴. 다시 계산할 때 해당 로그는 무시 |
| `reset` | 학습 진행도 초기화. 이 시점부터 새 카드로 취급 |

- 카드의 FSRS 상태(안정도, 난이도, 다음 복습일)는 **캐시**다.
- 필요할 때 `rebuildFromLogs(card, scheduler, params)`로 언제든 다시 만든다.
- **같은 로그 + 같은 알고리즘 + 같은 파라미터 → 항상 같은 결과**여야 하고, 테스트로 보장한다.
- 퍼즈(fuzz)는 `ts-fsrs`가 복습 시각·복습 횟수·기억 상태로 시드를 만들기 때문에 결정적이다 (테스트로 확인).
- 시각은 **UTC 밀리초**로 저장한다. FSRS-7이 소수 간격을 쓰기 때문이다.
- 통계용으로 당시 시간대 오프셋(분)을 같이 저장한다.
- 카드 내용을 편집해도 진행도는 유지한다. 초기화는 사용자가 명시적으로 `reset`할 때만 한다.

### 4.3 하루의 경계

- 하루는 **현지 시간 새벽 4시**에 시작한다 (설정 가능).
- "오늘의 새 카드 수" 같은 계산은 이 기준을 따른다.
- **학습 단계 카드**(같은 날 다시 보는 카드)는 예정 시각이 되면 다른 카드보다 먼저 보여준다.
  - 남은 카드가 학습 단계 카드뿐이면 최대 20분 앞당겨 보여준다 (Anki의 learn ahead).
  - 그보다 이르면 "잠깐 쉬어도 돼요" 화면에서 기다리거나 "지금 바로 보기"를 누른다.

### 4.4 답 버튼

| 모드 | 버튼 | FSRS 등급 |
|---|---|---|
| **기본: 2버튼** | 다시 / 알았음 | Again(1) / Good(3) |
| 설정에서 선택: 4버튼 | 다시 / 어려움 / 알았음 / 쉬움 | 1 / 2 / 3 / 4 |

- 각 버튼 위에 다음 복습까지의 간격을 작게 표시한다 (예: `10분`, `3일`).

### 4.5 사용자 설정

| 설정 | 기본값 | 범위 / 비고 |
|---|---|---|
| 목표 기억률 | 0.90 | 슬라이더 0.80–0.95 (4단계부터 예상 하루 복습량도 함께 표시) |
| 하루 새 카드 수 | 덱당 20개 | |
| 하루 복습 한도 | 없음 | FSRS 권장 |

### 4.6 복습 순서

- 기한이 지난 복습 카드를 먼저 보여준다. **기억 확률이 낮은 카드부터** 보여준다.
- 새 카드는 복습 사이에 섞어서 보여준다.
- **형제 카드 숨기기:** 같은 노트의 정방향/역방향 카드는 같은 날에 보여주지 않는다. 남은 형제 카드는 다음 날로 넘긴다.
- **어려운 카드:** 8번 이상 틀린 카드는 "어려운 카드" 표시를 붙이고 목록에 모아 보여준다. 자동 정지는 하지 않는다.

### 4.7 파라미터 최적화 (4단계)

- **조건:** 복습 기록이 약 1000회 이상 쌓였을 때
- **방법 A (앱 안에서):** `@open-spaced-repetition/binding`의 wasm 빌드를 쓴다.
  - 이 빌드는 `SharedArrayBuffer`가 필요하다. GitHub Pages는 필요한 응답 헤더(COOP/COEP)를 설정할 수 없어서, 서비스 워커로 우회해야 한다. **가능 여부는 확인이 필요하다.**
- **방법 B (대안):** 로그를 내보내서 PC의 Python 최적화 도구로 돌리고, 나온 파라미터를 앱에 붙여넣는다.
- 두 방법 모두 FSRS-7 최적화 지원 여부를 그 시점에 확인한다.

## 5. 카드 종류 시스템

### 5.1 구조

카드 종류 하나는 `src/core/cardTypes/` 안의 **모듈 하나**다. 앱의 나머지 코드는 카드 종류의 내부를 모른다.

```ts
interface CardType {
  id: string;               // 'basic', 'zh-word' — 한 번 정하면 바꾸지 않음
  version: number;          // 필드 구조가 바뀌면 올리고 migrate 작성
  name, shortName, description;
  fields: FieldDef[];       // { key, label, required?, lang?, input, autoFrom? }
  templates: TemplateDef[]; // { id, label, optional?, answer: 'reveal' | 'produce' }
  ttsField: string;         // 대표 발음 필드 (다음자 교정용)
  view(templateId, ctx): CardView;  // 앞면/뒷면 블록 + 읽을 텍스트 + (작문이면) 정답
  duplicateKey(fields): string;
  summary(fields): { title, sub };
  derive?(changedKey, fields, deps): Record<string, string>;  // 한자 → 병음 자동 채움
  migrate?(fromVersion, fields);
}
```

**화면은 블록만 그린다.** `view()`는 HTML이 아니라 블록 목록을 돌려준다.
- 블록 종류: `hanzi`, `pinyin`, `word`, `meaning`, `sentence`, `prompt`, `divider`, `memo`
- 화면(`src/ui/components/CardFace.tsx`)은 이 블록들만 그릴 줄 안다.
- 그래서 새 카드 종류가 기존 블록만 쓰면 화면 코드를 고칠 필요가 없다. 네이티브 앱으로 옮겨도 카드 종류 코드는 그대로 쓴다.

**답하는 방식 (`answer`)**
- `reveal`: 떠올린 뒤 정답을 본다.
- `produce`: 답을 직접 쓰거나 말한 다음, 정답과 글자 단위로 비교해서 보여준다(`src/core/answer/compare.ts`). 채점은 사용자가 버튼으로 한다.
  - 말하기는 브라우저 음성 인식을 쓴다. 안드로이드 Chrome에서는 인터넷이 필요하다.

규칙:
- **카드 종류 `id`와 필드 `key`는 절대 바꾸지 않는다.** 화면 이름(`label`)은 바꿔도 된다.
- `optional: true`인 템플릿(예: 역방향)은 덱 설정 스위치로 켜고 끈다(D6).

### 5.2 지금 있는 카드 종류

**① 중국어 단어 (`zh-word`)**

| 필드 | 필수 | 비고 |
|---|---|---|
| `hanzi` 한자 | ✓ | `zh-CN` |
| `pinyin` 병음 | | 한자를 입력하면 `pinyin-pro`로 자동 채움. 직접 고치면 그 뒤로는 자동으로 바꾸지 않음 |
| `meaning` 뜻 | ✓ | 한국어 |
| `memo` 메모 | | |

- **정방향:** 한자 → (병음 + 뜻)
- **역방향 (선택):** 뜻 → (한자 + 병음)
- **TTS:** 항상 `hanzi`를 읽는다. 다음자는 편집 화면의 "읽을 텍스트"로 교정한다 (§6).
- **중복 검사:** `hanzi` 기준

**② 기본 (`basic`)**

| 필드 | 필수 | 비고 |
|---|---|---|
| `front` 앞면 | ✓ | 언어는 덱 설정 (예: `id-ID`) |
| `back` 뒷면 | ✓ | 언어는 덱 설정 (예: `ko-KR`) |
| `memo` 메모 | | |

- **정방향:** 앞면 → 뒷면 / **역방향 (선택):** 뒷면 → 앞면
- **TTS:** 앞면을 읽는다.

**③ 중국어 작문 (`zh-sentence`)**

| 필드 | 필수 | 비고 |
|---|---|---|
| `ko` 한국어 문장 | ✓ | |
| `zh` 중국어 문장 | ✓ | |
| `pinyin` 병음 | | 중국어 문장에서 자동 채움 |
| `memo` 메모 | | |

- **한국어 → 중국어 (`produce`):** 한국어 문장을 보고 중국어로 쓰거나 말한다. 정답에서 빠진 글자와 틀린 글자를 표시한다.
- **중국어 → 한국어 (선택, `reveal`):** 읽기·듣기 연습.

### 5.3 새 카드 종류 추가하는 법

1. `src/core/cardTypes/<이름>.ts`에 `CardType`을 하나 만든다. 비슷한 기존 파일(`zhSentence.ts` 등)을 복사해서 시작하면 된다.
2. `src/core/cardTypes/registry.ts`의 `CARD_TYPES`에 한 줄 추가한다.
3. 필요하면 `cardTypes.test.ts`에 테스트를 추가한다. 모든 카드 종류의 앞/뒷면이 그려지는지는 기존 테스트가 자동으로 검사한다.

화면, 저장소, 스케줄러는 고칠 필요가 없다. 새 블록 종류가 필요할 때만 `Block` 타입과 `CardFace.tsx`에 추가한다.

### 5.4 나중에 추가할 후보

- 듣기 카드 (소리만 듣고 뜻)
- 빈칸 채우기
- 성조 색상 표시 (설정)

## 6. 음성 (재생과 받아쓰기)

**조건: 모두 무료.** 그래서 Google AI Studio의 **Gemini API 무료 키**를 쓴다 (2026-10 기준 TTS 모델 무료 제공).
- 사용자가 설정 › 자연스러운 음성에서 키를 붙여넣어 연결한다. 결제 정보는 필요 없다.
- 키는 이 기기의 설정에만 저장하고, **백업 파일에는 넣지 않는다.** 복원해도 이 기기의 키는 유지된다.
- 무료로 쓰면 Google이 보낸 텍스트와 녹음을 서비스 개선에 쓸 수 있다. 설정 화면에 안내한다.
- 무료 한도는 공개되지 않았고 바뀔 수 있다. 그래서 음성을 **한 번만 만들어 저장**하고, 실패하면 기기 음성으로 대신 읽는다.

### 6.1 재생 (`src/adapters/speech/speech.ts`)

재생 순서:
1. 저장된 음성 파일 (`audio` 표, 키 = 모델 | 목소리 | 언어 | 텍스트)
2. 없으면 Gemini TTS로 만들어 저장하고 재생 (인터넷 필요)
3. 안 되면 기기 내장 음성 (Web Speech API). 왜 안 됐는지 한 번 알려준다

세부 사항:
- **모델:** 키를 연결할 때 모델 목록에서 고른다. 선호 순서는 `gemini-3.8-flash-tts` → `gemini-3.8-flash-lite-tts` → `gemini-3.1-flash-tts-preview`이고, 없으면 이름에 `-tts`가 든 모델을 쓴다.
- **요청:** `responseModalities: ['AUDIO']`과 기본 목소리(`Kore` 등)로 보낸다. 짧은 단어는 언어를 잘못 짐작할 수 있어서 "Say in Mandarin Chinese …: 银行"처럼 언어를 알려준다.
- **응답:** 헤더 없는 16비트 PCM(24kHz)이 온다. WAV 헤더를 붙여 저장한다.
- **미리 만들기:** 단어를 저장하거나 고치면 그 단어의 음성을 미리 만든다. 설정의 "모든 단어 음성 미리 만들기"는 1초 간격으로 차례대로 만들고, 한도에 걸리면 30초 기다렸다가 다시 시도한다. 두 번 더 실패하면 멈춘다.
- **목소리를 바꾸면** 새 목소리로 다시 만들어야 한다. 남은 개수가 다시 표시된다.
- **다음자 교정:** 편집 화면의 "읽을 텍스트"(`ttsOverride`)를 쓴다.

### 6.2 받아쓰기 (말해서 답하기, `src/ui/useVoiceAnswer.ts`)

- **Gemini가 연결돼 있으면:** 마이크로 녹음(최대 20초)하고, 16kHz 모노 WAV로 바꿔 `gemini-flash-latest`에 보낸다. 이 모델이 안 되면 `gemini-flash-lite-latest`로 보낸다.
  - 지시문은 "학습자가 말한 그대로 받아쓰고, 틀려도 고치지 말 것, 간체자로"이다.
  - 실시간 스트리밍(Live API) 대신 "녹음 → 받아쓰기"를 쓴다. 짧은 답에는 이쪽이 더 정확하고 간단하다.
- **연결이 안 돼 있으면:** 브라우저 음성 인식을 쓴다.
- 받아쓴 글자는 답 칸에 들어가고, 고칠 수도 있다. 그다음 정답과 비교한다(§5.1).

## 7. 화면 구성

하단 탭은 4개다: **오늘 · 추가 · 덱 · 설정**

### 오늘 (홈)

- 오늘 남은 복습 수와 새 카드 수를 크게 보여준다.
- 큰 "시작" 버튼을 둔다.
- 아래에 덱별 목록을 둔다.
- 백업 알림이 필요할 때만 조용히 한 줄로 보여준다.

### 복습 화면

- **전체 화면.** 카드 내용만 가운데 크게 보여준다.
- **아무 곳이나 탭하면 뒤집힌다.**
- **답 버튼은 화면 하단(엄지 영역)에 둔다.** 터치 영역은 최소 48dp.
- **상단 바:**
  - 왼쪽: 닫기
  - 오른쪽: 되돌리기, 편집, 발음
  - 진행률은 얇은 선으로 표시
- 화면에 다른 장식은 넣지 않는다.

### 추가

1. 덱을 고른다 (마지막 선택을 기억). 카드 종류는 덱 기본값을 따른다.
2. 필드를 입력한다. 중국어 단어 카드는 한자를 입력하면 병음이 자동으로 채워진다.
3. 중복이 있으면 입력하는 중에 바로 경고한다.
4. **"저장 후 다음"을 누르면 키보드가 닫히지 않고, 첫 필드로 돌아간다.**
5. 저장되면 "되돌리기"가 있는 짧은 알림을 보여준다.

### 덱

- 덱 목록, 노트 검색, 편집/삭제
- **덱 설정:**
  - 카드 종류 기본값
  - 역방향 카드 스위치
  - 하루 새 카드 수
  - 언어 (TTS용)
  - 자동 재생

### 가져오기 (2단계)

- **입력 방법:** 붙여넣기 (스프레드시트에서 복사한 탭 구분 텍스트) 또는 CSV 파일
- **진행 순서:**
  1. 열 매핑 미리보기 (어느 열이 한자/뜻인지)
  2. 중복 처리 선택 (건너뛰기 / 덮어쓰기)
  3. 가져오기
- **PC → 폰으로 옮기는 방법:** PC의 Google Sheets에서 정리한다. 그다음 폰에서 Sheets 앱으로 복사해 붙여넣거나, CSV를 Drive에 저장해서 폰에서 고른다.
  - PC와 폰은 데이터 저장소가 따로라서, PC에서 앱을 열어 입력하는 방식은 쓰지 않는다.

### 설정

| 항목 | 내용 |
|---|---|
| 테마 | 시스템/라이트/다크, 강조 색상 몇 가지, 완전 검정(AMOLED) 옵션 |
| 글자 크기 | |
| 답 버튼 | 2개 / 4개 |
| 목표 기억률 | |
| 하루 시작 시각 | |
| 음성 | 언어별 음성 선택 |
| 백업/복원 | |
| 알고리즘 | FSRS 버전 |

## 8. 디자인 원칙

1. **라이트와 다크를 각각 따로 디자인한다.** 색은 CSS 변수(토큰)로만 정의한다.
2. **대비는 WCAG AA 이상**으로 맞춘다.
3. **한자는 크게** 보여준다.
   - 폰트는 시스템 CJK 폰트(안드로이드는 Noto Sans CJK)를 쓴다.
   - 별도 폰트를 쓰게 되면 외부 CDN이 아니라 앱 안에 포함한다.
4. **한 손 사용.** 자주 쓰는 조작은 모두 화면 아래쪽 절반에 둔다.
5. **애니메이션은 짧고 절제한다.** 기기의 "애니메이션 줄이기" 설정을 따른다.
6. **설정은 꼭 필요한 것만** 둔다. 고급 설정은 한 단계 안쪽에 숨긴다.
7. **구현 전에 시안부터 확정한다(0단계).** 클릭할 수 있는 목업으로 색상, 복습 화면, 추가 화면을 먼저 정한다.

## 9. 기술 구조

### 스택

| 역할 | 선택 |
|---|---|
| 빌드 | Vite |
| UI | React + TypeScript |
| PWA (오프라인, 설치) | `vite-plugin-pwa` |
| 저장소 | Dexie (IndexedDB) |
| 스케줄러 | `ts-fsrs` |
| 병음 | `pinyin-pro` |
| 테스트 | Vitest (단위), Playwright (모바일 화면 E2E) |
| 배포 | GitHub Actions → GitHub Pages, base path `/flashcards/` |

### 폴더 구조

```
src/
  core/        순수 TypeScript. 브라우저·React·Dexie를 import하지 않음
    scheduler/   FSRS 어댑터, rebuildFromLogs, 복습 대기열
    cardTypes/   basic.ts, zhWord.ts, registry.ts
    model/       타입 정의, ID, 날짜 경계
    io/          백업 내보내기/가져오기, TSV/CSV 파싱
  adapters/    바꿔 끼우는 부분
    storage/     dexie (네이티브 전환 시 SQLite)
    tts/         webSpeech, (나중) googleCloud / azure
  ui/          React 화면, 테마 토큰
```

### 의존 방향

```
ui → core ← adapters
```

- `core`는 아무것도 import하지 않는다.
- lint 규칙으로 이 방향을 강제한다.

### 네이티브 전환 시

1. Capacitor로 감싼다.
2. 어댑터만 바꾼다: 저장소 → SQLite, TTS → 안드로이드 TextToSpeech, 알림 → Local Notifications.

## 10. 데이터 모델

- 모든 ID는 `crypto.randomUUID()`로 만든다. 나중에 병합이나 동기화를 대비한 것이다.
- Dexie 스키마 버전과 마이그레이션을 관리한다.

```ts
Deck {
  id, name, defaultTypeId, createdAt,
  settings: {
    reverseEnabled: boolean,
    newPerDay: number,
    autoplay: 'front' | 'back' | 'off',
    langs: { front?: string, back?: string },   // basic 카드용 TTS 언어
  }
}

Note {
  id, deckId, typeId, typeVersion,
  fields: Record<string, string>,
  ttsOverride?: Record<string, string>,
  tags: string[], createdAt, updatedAt
}

Card {
  id, noteId, templateId,          // (noteId, templateId) 고유
  hidden: boolean,                 // 역방향 스위치 OFF일 때 true
  suspended: boolean,
  buriedUntilDay?: number,
  // ↓ 캐시 (ReviewLog로 재계산 가능)
  fsrs?: { /* ts-fsrs 카드 상태 그대로 */ },
  due: number, lapses: number, reps: number, lastReviewAt?: number
}

ReviewLog {                        // 추가만 함
  id, cardId,
  kind: 'review' | 'void' | 'reset',
  rating?: 1 | 2 | 3 | 4,
  voidsId?: string,
  at: number,                      // UTC ms
  tzOffsetMin: number,
  durationMs?: number,
  scheduler: string                // 예: 'fsrs-6@ts-fsrs-5.4.2'
}

Audio {
  key, text, lang, provider, voice, blob, createdAt
}

Settings {                         // 단일 레코드
  desiredRetention, schedulerId, fsrsParams?, dayStartHour,
  buttons: 2 | 4, theme, accent, fontScale, voices, lastBackupAt
}
```

### 백업 파일 형식

```json
{
  "format": "flashcards-backup",
  "version": 1,
  "exportedAt": "…",
  "decks": [],
  "notes": [],
  "cards": [],
  "reviewLogs": [],
  "settings": {}
}
```

- 음성 파일은 기본적으로 제외한다. 다시 생성할 수 있기 때문이다.
- 가져올 때 카드 캐시는 무시하고 로그로 다시 계산한다.

## 12. 테스트 원칙

- **core 단위 테스트 (필수)**
  - 같은 로그로 다시 계산하면 같은 상태가 나옴 (결정성)
  - `void`/`reset` 처리
  - 역방향 스위치 끄기/켜기 후 기록이 유지됨
  - 형제 카드 숨기기
  - 새벽 4시 경계와 시간대 변경
  - TSV/CSV 파싱 (따옴표, 줄바꿈, 빈 칸)
  - 병음 자동 채움
- **E2E (Playwright, 모바일 화면)**
  - 카드 추가 → 복습 → 되돌리기
  - 백업 → 데이터 삭제 → 복원
- **푸시 전에 lint, 타입 검사, 테스트를 모두 통과해야 한다.**
